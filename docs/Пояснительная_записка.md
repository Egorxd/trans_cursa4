# Пояснительная записка к матричному транслятору

Matrix Translator 1.0.0

Работа реализует транслятор специализированного языка матричных вычислений в Python. Исходный файл проходит лексический, синтаксический и семантический анализ. Корректная программа преобразуется в Python-код с использованием NumPy; вычисления выполняются при отдельном запуске этого кода. В комплект входят исходники, грамматика, готовые исполняемые файлы, тесты, инструкция по сборке и справка пользователя.

## Техническое задание

Исходное техническое задание сохранено в `docs/Техническое_задание.docx`. Требуется поддержать числовые и матричные переменные, прямоугольные непустые матрицы, выражения, присваивания, комментарии и вывод. Операции над матрицами включают сложение, вычитание, матричное умножение, транспонирование, определитель, обратную матрицу и ранг.

Транслятор обязан выявлять необъявленные и повторно объявленные имена, ошибки типов, аргументов функций, структуры литералов и размеров матриц. При ошибке исходного текста выходная программа не создаётся. Диагностика содержит причину, строку и столбец. Обращение вырожденной матрицы проверяется при выполнении программы с учётом вещественной погрешности.

Преподаватель дополнительно требует исходники грамматики и программы, текстовую инструкцию сборки, работоспособный скомпилированный транслятор, тестовый пример с дампами потоков и справку для пользователя. Все перечисленные материалы представлены в структуре проекта. Dockerfile добавлен для воспроизводимой сборки и запуска в Linux-контейнере; фактическая проверка Docker на компьютере подготовки не проводилась из-за отсутствия Docker.

## Язык и грамматика

Язык не претендует на совместимость с внешним стандартом. Идентификаторы состоят из ASCII-букв, цифр и `_`, не начинаются с цифры и чувствительны к регистру. Ключевые слова — `matrix`, `number`, `print`. Имена встроенных функций также зарезервированы для объявления переменных. Пробелы и комментарии пропускаются лексическим анализатором.

Числовой токен допускает последовательность десятичных цифр с необязательной точкой либо точку с последующими цифрами, а также необязательную экспоненту `e` или `E` с необязательным знаком. Знаки `+` и `-` являются отдельными токенами, что позволяет одинаково обрабатывать отрицательные числа и унарные операции. Комментарии задаются через `//`, `#` и `/* ... */`.

Грамматика допустимых конструкций в EBNF:

```text
program        = { statement } ;
statement      = type identifier "=" expression ";"
               | identifier "=" expression ";"
               | "print" "(" expression ")" ";" ;
type           = "matrix" | "number" ;
expression     = sum ;
sum            = product { ("+" | "-") product } ;
product        = unary { "*" unary } ;
unary          = ("+" | "-") unary | primary ;
primary        = unsigned_number
               | identifier
               | matrix_literal
               | "(" expression ")"
               | identifier "(" [ arguments ] ")" ;
arguments      = expression { "," expression } ;
matrix_literal = "[" row { "," row } "]" ;
row            = "[" signed_number { "," signed_number } "]" ;
signed_number  = [ "+" | "-" ] unsigned_number ;
```

Список аргументов допускается в синтаксическом анализе, чтобы семантический анализ мог сообщить фактическое и требуемое число аргументов. У каждой встроенной функции ровно один аргумент. Реальная грамматика `grammar/parser.y` также распознаёт `[]` и пустые строки матрицы, после чего семантический анализ отвергает их с понятным объяснением. Матрицы с разной длиной строк отвергаются на той же стадии. Нецифровые элементы литерала являются синтаксической ошибкой.

В Bison приоритеты задаются через `%left '+' '-'`, `%left '*'` и `%precedence UNARY`. Операции `+`, `-`, `*` имеют левую ассоциативность, унарные знаки — более высокий приоритет. Скобки сохраняют требуемое пользователем дерево вычислений. Сборка грамматики запускается с предупреждениями, трактуемыми как ошибки; конфликтов разбора не обнаружено.

## Семантика и проверка размеров

Поддерживаются два типа: `number` и `matrix`. Переменная должна иметь начальное значение и может быть объявлена один раз. Область видимости единая, команды обрабатываются последовательно. Переменная помещается в таблицу имён только после проверки её начального выражения; использование собственного имени в первом объявлении отклоняется.

Запись символа содержит имя, тип, текущие размеры матрицы и числовой идентификатор для генерации кода. Тип не меняется при присваивании, размеры матрицы могут меняться. Размеры вычисляются статически, поскольку язык не содержит внешнего ввода матриц, ветвлений, циклов или индексирования. Каждый узел выражения получает тип и размеры, соответствующие состоянию программы в месте его использования.

Для матрицы размера `m × n` применяются следующие правила:

| Конструкция | Условие | Тип и размер результата |
| --- | --- | --- |
| Литерал матрицы | `m > 0`, `n > 0`, одинаковая длина строк | `matrix`, `m × n` |
| `A + B`, `A - B` | `shape(A) = shape(B)` | `matrix`, размер `A` |
| `A * B` | `cols(A) = rows(B)` | `matrix`, `rows(A) × cols(B)` |
| `transpose(A)` | Аргумент — матрица | `matrix`, `n × m` |
| `det(A)` | Аргумент — квадратная матрица | `number` |
| `inverse(A)` | Аргумент — квадратная матрица | `matrix`, `m × m` |
| `rank(A)` | Аргумент — матрица | `number`, целое значение |
| Число `op` число | `op` — `+`, `-` или `*` | `number` |
| Унарный знак | Число или матрица | Тип и размер операнда |

Смешение матрицы и числа в бинарной операции не поддерживается. Это исключает неявное расширение размеров при выполнении NumPy. Обращение квадратной матрицы дополнительно проверяется на численную вырожденность во время выполнения.

Пример изменения формы:

```text
matrix A = [[1, 2]];       // 1x2
A = transpose(A);         // 2x1
matrix C = A * [[3, 4]];  // 2x2
```

Анализ присваивания сначала использует старое значение `A` для правой части, затем записывает новые размеры для следующих команд. Поэтому `A = transpose(A);` обрабатывается правильно. Таблица символов реализована связанным списком; поиск требует `O(V)` сравнений для `V` объявленных переменных. Это простая реализация для учебных программ без требования к обработке больших проектов.

## Архитектура программы

Транслятор состоит из пяти основных модулей и автоматически создаваемого кода анализаторов.

| Файл | Назначение |
| --- | --- |
| `src/main.c` | Командная строка, чтение файлов, последовательность стадий, безопасная запись результата |
| `grammar/lexer.l` | Лексические правила Flex, комментарии, позиции токенов и ограничения |
| `grammar/parser.y` | Грамматика Bison и построение AST |
| `src/ast.h`, `src/ast.c` | Узлы AST, списки, управление памятью и диагностика |
| `src/semantic.c` | Таблица переменных, проверка типов и размеров |
| `src/codegen.c` | Генерация Python и функций проверки вычислений |
| `generated/` | Результаты обработки .y/.l, пригодные для сборки одним компилятором C |

Последовательность обработки: чтение UTF-8 → Flex → Bison → дерево программы → семантический анализ → генерация Python → завершение записи. Никакие выражения исходной программы не выполняются самим транслятором.

AST содержит узлы чисел, переменных, матричных литералов, бинарных и унарных операций, вызовов функций. Команды представлены отдельными узлами объявления, присваивания и вывода. Все объекты AST и строки выделяются в общей арене с регистрацией блоков. Память освобождается целиком в конце работы, включая ошибку разбора.

Flex сохраняет начало каждого токена. Счётчики строк и столбцов учитывают UTF-8 в комментариях; табуляция занимает один столбец. Bison передаёт координаты в AST. Ошибки анализаторов и семантики выводятся единым механизмом, который сохраняет первую диагностику.

Входной файл ограничен 16 МиБ, количество значимых токенов — 100000, глубина AST выражения — 512. Эти ограничения предотвращают чрезмерное потребление памяти и рекурсивный обход слишком глубокого дерева. Ошибка ограничения токенов или глубины не приводит к созданию выходной программы.

## Генерация Python

Числовые значения нормализуются через `strtod` и выводятся с 17 значащими цифрами. Для записи, не содержащей точки или экспоненты, добавляется `.0`, чтобы обычная числовая арифметика выполнялась с вещественной точностью. Это также устраняет проблему ведущих нулей, допустимых во входном языке, но недопустимых в десятичных целых литералах Python. Матрицы создаются как `np.array(..., dtype=np.float64)`.

Имена исходного языка заменяются на `__v0`, `__v1` и далее. Пользовательские имена не могут конфликтовать с Python-ключевыми словами, импортом NumPy или вспомогательными функциями. Исходный путь записывается как экранированная строка Python, поэтому пробелы, обратные косые черты и кавычки обрабатываются корректно.

| Исходная конструкция | Генерируемая конструкция |
| --- | --- |
| `[[1, 2], [3, 4]]` | `np.array([[1.0, 2.0], [3.0, 4.0]], dtype=np.float64)` |
| `A + B`, `A - B` | `(__v0 + __v1)`, `(__v0 - __v1)` |
| `A * B` для матриц | `(__v0 @ __v1)` |
| `a * b` для чисел | `(__v0 * __v1)` |
| `transpose(A)` | `__transpose(__v0, line, column)` |
| `det(A)` | `__det(__v0, line, column)` |
| `rank(A)` | `__rank(__v0, line, column)` |
| `inverse(A)` | `__inverse(__v0, line, column)` |
| `print(expr)` | `print(__finite(expr, line, column))` |

Скобки сохраняются вокруг операций, поэтому порядок вычислений не зависит от различий приоритетов целевого языка. Значение правой части присваивания также проходит через `__finite`. Транспонирование возвращает копию массива. Изменение отдельных элементов не предусмотрено, поэтому передача массива между переменными не меняет ранее вычисленные значения.

Генерируемый файл самодостаточен относительно исходного проекта: ему нужны только Python и NumPy. В начале программы стандартные выходные потоки настраиваются на UTF-8. Это обеспечивает одинаковую кодировку русских диагностик в консоли и при перенаправлении потоков, включая обычный запуск Windows PowerShell с системной Windows-1251. Проверяется отсутствие NumPy, конечность результатов, ошибки линейной алгебры и переполнение. До каждой команды сохраняются её координаты. Функции матричной алгебры получают собственные координаты, что уточняет позицию ошибки обращения. Перехваченные вычислительные ошибки выводятся без стека Python.

## Численная точность

Элементы матриц хранятся в float64. Ранг определяется через сингулярные числа `s` из `np.linalg.svd(A, compute_uv=False)`. Для ненулевого `s_max` ранг равен количеству значений, удовлетворяющих условию `s / s_max > max(m, n) * eps`. Для нулевой матрицы возвращается `0`.

Это относительная форма порога `tol = s_max * max(m, n) * eps`, применяемого по умолчанию в [NumPy matrix_rank](https://numpy.org/doc/stable/reference/generated/numpy.linalg.matrix_rank.html). Деление на `s_max` позволяет не терять абсолютный порог при очень малом масштабе матрицы. Сингулярные числа используются в соответствии с интерфейсом [NumPy SVD](https://numpy.org/doc/stable/reference/generated/numpy.linalg.svd.html).

Перед вычислением `inverse(A)` программа проверяет, что численный ранг квадратной матрицы равен её размеру. Затем вызывается `np.linalg.inv`. Ошибки SVD и обращения перехватываются. Сравнение определителя с точным нулём для принятия решения об обращении не применяется: оно зависело бы от масштаба элементов и было бы чувствительным к округлению.

Например, диагональная матрица `[[1, 0], [0, 1e-18]]` имеет математический ранг два, но при выбранном относительном пороге признаётся численно вырожденной. Её обращение отклоняется. Матрица `[[1e-200, 0], [0, 1e-200]]` имеет численный ранг два и обращается успешно, поскольку масштаб всех сингулярных чисел изменяется одинаково.

Порог отражает округление машинной арифметики, а не погрешность измерений исходных данных. Пользователь не задаёт индивидуальную точность. Вычисления не являются символьными: возможны округление очень малых результатов до нуля и небольшие отклонения от точного ответа. Переполнение и нечисловые результаты диагностируются.

## Работа с файлами и переносимость

Командная строка соответствует заданию: `translator input.txt -o output.py`. Некорректный запуск выводит краткую справку. Ошибки открытия, чтения, создания и записи файлов завершают работу с диагностикой. Для Windows используются широкие пути и UTF-8 для вывода сообщений, поэтому поддерживаются кириллица и пробелы в путях.

После успешного семантического анализа код записывается во временный файл в папке результата. Файл закрывается с проверкой ошибок, затем переименовывается в конечный путь. При ошибке до замены прежний файл сохраняется. Входной и выходной файлы проверяются на совпадение, включая жёсткие ссылки. Программа не создаёт недостающие родительские папки.

Windows-сборка использует GCC UCRT64 и не требует сторонних DLL. Зависимости Windows-версии проверены по таблице импорта. Linux-версия поставляется как статический ELF для x86_64. Исходники совместимы с C11; платформенные функции ограничены модулем `main.c`.

Dockerfile содержит стадию сборки, которая регенерирует анализаторы, компилирует C и выполняет автоматические тесты. В финальном образе остаются транслятор, Python, NumPy и необходимые библиотеки Linux. Полная инструкция сборки и ограничения проверки контейнера указаны в `BUILD.txt`.

## Тестирование и примеры

Описание каждого теста и ожидаемые числовые значения находятся в `tests/cases.json`. В `tests/valid` представлены допустимые программы, включая программы с ожидаемой ошибкой при выполнении; в `tests/invalid` — ошибки трансляции. Сценарий `tests/run_tests.py` запускает транслятор как отдельный процесс, затем выполняет Python-файл тем же интерпретатором, которым запущены тесты.

Проверяются все операции, прямоугольное умножение, ранги квадратной, прямоугольной и нулевой матриц, приоритеты, скобки, вложенные функции и изменение размеров при присваивании. Отрицательные тесты покрывают объявления, типы, аргументы, матричные литералы, все случаи несовместимости размеров, неквадратные матрицы, лексические и синтаксические ошибки.

Отдельные проверки контролируют вырожденность, почти вырожденные и малые по масштабу матрицы, переполнение, запуск без аргументов, отсутствующие файлы, ошибки записи, совпадение файлов, UTF-8/BOM, пути с кириллицей и пробелами, ограничения размера, токенов и глубины. Регрессионный тест запускает сгенерированную программу с настройками `PYTHONIOENCODING=cp1251` и `PYTHONUTF8=0` и проверяет, что русская вычислительная ошибка всё равно приходит в UTF-8. Дополнительно проверяется остаток произведения `A * inverse(A)` относительно единичной матрицы. Для каждой ошибки исходного языка подтверждается отсутствие нового выходного файла и сохранение ранее существовавшего результата.

Числовые ответы сравниваются с относительным допуском `1e-9` и абсолютным `1e-10`; остаток обращения проверяется по максимальному отклонению менее `1e-9`. Тесты проверяют правильность чисел, а не оформление пробелов NumPy. Результат проверки на каждой платформе — 93 из 93 пройденных тестов. Журналы сохранены в `verification/tests.log` и `verification/tests-linux.log`.

Для примера из задания:

```text
A = [[1, 2], [3, 4]]
B = [[5, 6], [7, 8]]
A+B = [[6, 8], [10, 12]]
A-B = [[-4, -4], [-4, -4]]
A*B = [[19, 22], [43, 50]]
transpose(A) = [[1, 3], [2, 4]]
det(A) приблизительно -2
rank(A) = 2
inverse(A) = [[-2, 1], [1.5, -0.5]]
```

Полный входной текст сохранён в `examples/input.txt`, сформированная программа — в `examples/output.py`. Реальные дампы транслятора находятся в `examples/translation.stdout.txt` и `examples/translation.stderr.txt`, а дампы выполнения — в `examples/stdout.txt` и `examples/stderr.txt`. Команды воспроизведения приведены в `examples/commands.txt`. Ошибка размеров представлена в `tests/invalid/multiply_shape.txt`, а обращение вырожденной матрицы — в `tests/valid/singular_inverse.txt`.
